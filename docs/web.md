# Web UI

`ano web` は、ブラウザからエージェントと対話するためのサーバーを起動します。セッションごとに作業フォルダ・権限・承認モード・プリセットを選んで会話でき、承認が必要な呼び出しはブラウザで許可・拒否します。

現在は同時に1セッションまでです。API とセッション表は最初からセッション ID 単位で作ってあり、複数のセッションを並行して動かす拡張を予定しています。

## 起動

```sh
ano web                                  # http://127.0.0.1:8787
ano web --bind 127.0.0.1:9000 --workspace ~/src/my-project
```

起動すると、トークン付きの URL が表示されます。

```text
ano web UI: http://127.0.0.1:8787/?token=0f3c...
```

この URL を開くと、ブラウザはトークンを Cookie に保存し、アドレスバーからトークンを消した `/` へ移ります。トークンは起動のたびに変わります。`ANO_WEB_TOKEN` を設定すると、その値を使います（ブックマークで開き直したい場合）。URL と Cookie にそのまま入れるため、使える文字は英数字と `-`・`_`・`.`・`~` だけです。

| オプション | 内容 |
| --- | --- |
| `--bind ADDRESS` | 待ち受けるアドレスとポート（既定 `127.0.0.1:8787`）。ループバックアドレスだけを受け付けます |
| `--workspace PATH` | セッション作成画面の作業フォルダの初期値（既定はカレントディレクトリ） |
| `--config` / `--user` | ほかのコマンドと同じ。セッションはこのユーザーのポリシーとスキルで動きます |

Ctrl+C で止めると、実行中のターンを中断し、MCP の接続を閉じてから終了します。

## 画面

- **セッションの作成。** 作業フォルダ（`~` はホームディレクトリ）、環境、プリセット、権限（ファイルの書き込み・コマンドの実行・Web ページの取得）、承認モードを選んで開始します。環境を選ぶと、権限と承認モードは環境の設定に従います。環境に `workspace` があれば、その作業フォルダを使います。
- **会話。** 回答は生成中から表示し、確定すると Markdown として整形します。tool の呼び出しと結果は折りたたんだ行で表示し、開くと引数と出力の全体（長いものは先頭だけ）を読めます。Enter で送信、Shift+Enter で改行です（日本語入力の変換中の Enter では送信しません）。
- **承認。** 承認が必要な呼び出しは、対象と引数を示したカードで許可・拒否を選びます。`auto` では、判定用モデルが迷った呼び出しだけがカードになります。
- **停止と終了。** 「停止」は実行中のターンを中断します（完了した操作は元に戻りません）。会話は続けられます。「セッションを終了」はセッションを閉じます。会話はサーバーのメモリにだけあり、終了やサーバーの停止で消えます。
- **計画・使用量・セッション情報。** 幅の広い画面では右側に表示します。

ページを再読み込みしたり、接続が途切れて再接続したりしても、それまでのイベントと生成中の文章を受け取り直して表示を復元します。

## セッション

セッションは `ano chat` と同じ組み立てで動きます。環境を選ばない場合の実行設定は次のとおりです。

| 項目 | 値 |
| --- | --- |
| 環境名 | `web`（原文履歴やセッションの記録に使われます） |
| tool のポリシー | `--user` のユーザーのポリシー |
| 承認モード | 画面で選んだもの。省略時は `[agent] approval_mode`（既定 `auto`） |
| 接続先・モデル | 選んだプリセット。`default` は `[agent]`（または `[agent.roles].default`） |

環境を選んだ場合は、`--environment` を付けた `ano chat` と同じく、環境の権限・承認モード・接続先に従います。環境の権限を画面から広げることはできません（権限や承認モードを一緒に送るとエラーになります）。

## API

ページが使う API です。すべて Cookie のトークンが必要です（無ければ 401）。

| メソッドとパス | 内容 |
| --- | --- |
| `GET /api/options` | 作成画面の選択肢（環境・プリセット・承認モード・作業フォルダの初期値） |
| `GET /api/sessions` | セッションの一覧 |
| `POST /api/sessions` | セッションを作成（`workspace`・`environment`・`preset`・`allow_writes`・`allow_exec`・`allow_web`・`approval_mode`）。上限に達していれば 409 |
| `GET /api/sessions/{id}` | セッションの設定・実行中か・計画・使用量 |
| `DELETE /api/sessions/{id}` | セッションを終了（実行中のターンは中断） |
| `POST /api/sessions/{id}/messages` | `{"text": "..."}` でターンを開始。実行中なら 409 |
| `POST /api/sessions/{id}/cancel` | 実行中のターンを中断 |
| `POST /api/sessions/{id}/approvals/{approval}` | `{"approved": true}` で承認要求に答える。待っている要求が無ければ 404 |
| `GET /api/sessions/{id}/events` | イベントの Server-Sent Events |

イベントは `{"type": ...}` の JSON です。番号付きのもの（`user_message`・`turn_started`・`message`・`agent`・`approval_requested`・`approval_resolved`・`turn_finished`・`closed`）はセッションごとに保持し、`Last-Event-ID` を付けて接続し直すとその続きから送ります。生成中の文章（`delta`）と推論中の通知（`reasoning`）は保持せず、接続時に生成中の文章全体を `partial` で送ります。`agent` は実行ループのイベント（Webhook の `recent_events` と同じ形）です。

## 画面の実装（naui）

画面は [naui](https://crates.io/crates/naui) の Web（DOM）バックエンドで Rust から組み立て、WebAssembly にビルドしています。ソースは [`web-ui/`](../web-ui) にあり、workspace のメンバーですが既定のビルド対象ではありません（wasm32 でだけビルドします）。

ビルドした JS と wasm は `src/interface/web/assets/pkg/` にコミットし、`ano` のバイナリに埋め込みます。そのため `ano` 自体のビルドに wasm のツールチェーンは要りません。`web-ui/` を変えたら、次のコマンドで作り直してコミットします。

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.127   # Cargo.lock の wasm-bindgen と同じ版
web-ui/build.sh
```

naui の共通 API に無いもの（回答の Markdown の HTML、Enter での送信、末尾へのスクロール、スタイルシートが使うクラス）は、naui が公開する DOM 要素を通して扱います（`web-ui/src/dom.rs`）。Markdown はサーバーが HTML にし、生の HTML はエスケープし、リンクは `http`・`https`・`mailto` と相対パスだけを残します。

## セキュリティ

- ループバックアドレスでだけ待ち受けます。別の端末から使う場合は SSH のポート転送などを使ってください。
- ページと API はトークンを要求します。Cookie は `HttpOnly`・`SameSite=Strict` で、ほかのサイトからの要求には付きません。同じ PC のほかのユーザーも、トークンが無ければ操作できません。
- Content-Security-Policy で、スクリプトをこのサーバーのものだけに限り、回答に含まれる外部の画像も読み込ませません（URL にデータを載せた送信を防ぐため）。
- セッションは `ano` を起動したユーザーの OS 権限で、選んだ作業フォルダの中で動きます。書き込みとコマンド実行は、信頼する作業フォルダでだけ許可してください。
