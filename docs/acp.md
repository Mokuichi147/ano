# エディタとの連携（ACP）

`ano acp` は、ano を [Agent Client Protocol](https://agentclientprotocol.com/)（ACP）のエージェントとして動かします。Zed など ACP に対応したエディタが `ano acp` を起動し、標準入出力で JSON-RPC をやり取りします。エディタの画面から依頼すると、エディタで開いたフォルダを作業フォルダとして ano が作業し、回答・思考・tool の呼び出し・差分・作業計画がエディタに表示されます。承認が必要な呼び出しは、エディタの確認画面で許可・拒否します。

## エディタの設定

エディタのエージェントの設定に、起動するコマンドとして `ano acp` を登録します。Zed では `settings.json` の `agent_servers` に書きます（設定の形式は Zed のドキュメントで確認してください）。

```json
{
  "agent_servers": {
    "ano": {
      "type": "custom",
      "command": "ano",
      "args": ["acp", "--allow-writes", "--allow-exec", "--approval-mode", "ask"],
      "env": {}
    }
  }
}
```

- エディタは ano をシェルを通さずに起動することがあります。`ano` が見つからない場合は `command` にフルパス（`~/.cargo/bin/ano` を展開したものなど）を書きます。
- API キーなどの環境変数は、エディタから起動したプロセスに渡らないことがあります。OS 標準の設定ディレクトリの `.env`（`config.toml` の隣）に書くと、どこから起動しても読み込みます（[API キー](configuration.md)）。`env` に書くこともできます。
- エディタが ano を起動するフォルダはエディタによって異なるため、`./.ano/config.toml` が読まれるとは限りません。プロジェクトごとの設定を使う場合は `"args": ["--config", "/path/to/config.toml", "acp", ...]` のように明示します。

## オプション

| オプション | 内容 |
| --- | --- |
| `--allow-writes` | `workspace_write`・`workspace_edit`・`workspace_move`・`workspace_delete` によるファイルの変更を許可します |
| `--allow-exec` | `workspace_exec` によるコマンドの実行を許可します（1回ごとに承認モードで判定します） |
| `--approval-mode MODE` | 承認が必要な呼び出しの、最初の承認モード（`ask`・`auto`・`allow`・`deny`）。既定は `[agent].approval_mode`（未設定なら `auto`）。エディタからセッションごとに変えられます |
| `--preset NAME` | セッションを `[presets]` のプリセットで始めます。エディタからセッションごとに切り替えられます |
| `--environment NAME` | 設定した[実行環境](cli.md#実行環境)の権限・tool の制限・承認モード・モデルを使います。`--allow-writes`・`--allow-exec`・`--approval-mode` とは併用できず、承認モードはエディタから変えられません |
| `--disable-tool NAME` | tool を無効にします（複数指定可） |
| `--config` / `--user` | ほかのコマンドと同じ。セッションはこのユーザーのポリシーとスキルで動きます |

標準出力は ACP のメッセージだけに使います。警告やエラーは標準エラー出力に出るので、エディタのログで確認できます。エディタが接続を閉じると、実行中のターンを中断し、MCP の接続を閉じて終了します。

## セッション

エディタが開くセッションごとに、`ano chat` と同じ組み立てでエージェントを作ります。会話の状態はプロセスのメモリにだけあり、ano の終了で消えます（エディタからの会話の再開には未対応です）。`[history]` で原文履歴を有効にしている場合は、ほかのコマンドと同じく会話と tool の履歴を chronotope に記録します（[原文履歴](chronotope-history.md)）。

- **作業フォルダ。** エディタが渡したフォルダ（`cwd`）を作業フォルダにします。存在するフォルダの絶対パスでなければセッションを開けません。`--environment` の環境に `workspace` があるときは、そのフォルダを開いたセッションだけを受け付けます。AGENTS.md やスキルの一覧は、このフォルダから読み込みます。
- **権限。** `--environment` がなければ、コマンドラインの `--allow-writes`・`--allow-exec` に従います（環境名は `acp`）。
- **承認モード。** エディタのモードの切り替え（ACP の session mode と、`approval_mode` の設定項目の両方で提供します）で `ask`・`auto`・`allow`・`deny` を選べます。変更は、実行中のターンでも次の承認から反映します。`ask` では、呼び出しごとにエディタの確認画面で「Allow」「Reject」を選びます。エディタが答えずにターンを中断した場合は拒否として扱います。
- **プリセット。** 設定に `[presets]` があると、`preset` の設定項目（モデルの切り替え）を提供します。`default` は環境か `[agent]` の選択です。切り替えはターンとターンの間だけで、会話はそのまま新しいモデルで続きます。サブエージェントなどのロールも新しいモデルに従います。
- **中断と終了。** エディタの停止ボタン（`session/cancel`）で実行中のターンを中断します。完了した操作は元に戻りません。会話は続けられます。待っていた承認は拒否として扱い、実行中のまま残った tool の呼び出しは失敗として表示します。エディタがセッションを閉じる（`session/close`）と、実行中のターンを止めてから会話を破棄し、そのセッションだけの MCP 接続を閉じます。

## エディタに表示されるもの

| ano の出来事 | エディタでの表示 |
| --- | --- |
| 回答 | 生成中から逐次表示します |
| 推論の内容・要約 | 思考（thought）として表示します。接続先が返す場合だけです |
| tool の呼び出しと結果 | tool の種類（読み取り・検索・編集・実行・取得など）とタイトル、引数が指すファイルの場所、結果（長いものは先頭だけ）を表示します |
| `workspace_edit`・`workspace_write` | 変更内容を差分として表示します |
| `task_plan` の作業計画 | エディタの計画（plan）として表示します。止まっている工程は理由を添えて「未着手」にします |
| `delegate_task` とレビュー | サブエージェントを1つの tool の呼び出しとして表示し、その中の呼び出しも並べて表示します |
| 実行ループからの通知・MCP server の接続失敗・履歴の圧縮 | `[ano]` を付けた思考として表示します |

## エディタから渡される MCP server

エディタがセッションに MCP server を渡すと、そのセッションでは設定ファイルの MCP server に加えて、それらに直接接続します（stdio と HTTP。SSE には未対応です）。

- stdio の server は作業フォルダで起動し、エディタが指定した環境変数をそのまま渡します。HTTP の server には、エディタが指定したヘッダーを付けて接続します。
- ラベルはエディタが付けた名前から作り、英数字・`_`・`-` 以外は `_` に置き換えます。設定ファイルのラベルと重なると `-2` などを付けます。ポリシーの名前空間（`mcp:LABEL:TOOL`）はこのラベルで指定します。
- 呼び出しは、`require_approval` を省略した server と同じく、毎回承認モードで判定します。
- 使えない server（不正な URL など）は、警告を出して外します。

エディタが MCP server を渡さないセッションは、設定ファイルの MCP server の接続を共有します。

## 対応範囲

- 対応しているもの: 初期化、セッションの作成、プロンプト（テキスト・画像・音声（WAV / MP3）・埋め込まれたリソース・リソースへのリンク）、逐次表示、tool の呼び出しと差分、作業計画、承認（`session/request_permission`）、中断、セッションの終了（`session/close`）、承認モードとプリセットの切り替え、エディタから渡される stdio / HTTP の MCP server。
- 対応していないもの: 会話の保存と再開（`session/load`）、ACP の認証（`authenticate`。ChatGPT サブスクリプションは `ano auth login` で先にログインしておきます）、エディタのファイルシステムや端末を使った読み書き・実行（ano は自分の tool で作業フォルダを直接読み書きし、コマンドを実行します）、スラッシュコマンドの一覧。
- `ano chat` の `/goal`・`/compact` などのコマンドは使えません。依頼の文章としてそのままモデルに渡ります。

## セキュリティ

- ano はエディタが起動したユーザーの OS 権限で動きます。`--allow-writes`・`--allow-exec` は、信頼するプロジェクトを開くときだけ付けてください。`workspace_exec` はサンドボックスではありません。
- エディタから `allow` を選ぶと、確認なしにすべての呼び出しを許可します。`--allow-exec` との組み合わせは、壊れても復元できる環境に限ってください。承認モードを固定したい場合は、承認モードを決めた実行環境を `--environment` で指定します。
- エディタから渡される MCP server は、エディタの設定にある server です。stdio の server は ano のプロセスから起動され、設定ファイルの stdio の server と同じく ano の環境変数（API キーを含む）を引き継ぎます。信頼する server だけをエディタに登録してください。HTTP の server は http / https の URL だけを受け付けます。
- 開いたプロジェクトの AGENTS.md はモデルへの指示として使われます。信頼できないプロジェクトでは `project_instructions = []` の設定や実行環境を使ってください。
